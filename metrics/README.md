# Investigation Metrics: Definitions Before Counts

This portfolio publishes no case-volume or performance measurements. The table below defines candidate metrics for a future, appropriately authorized dataset; it is not populated with results.

| Metric | Definition | Guardrail |
|---|---|---|
| Intake volume | Cases received in a stated interval | Report scope, time window, and exclusions |
| Duplicate rate | Cases linked/merged as duplicates ÷ eligible intakes | Define duplicate criteria and review edge cases |
| Handling time | Elapsed active review time per case | Separate queue wait from reviewer work; report by complexity |
| Escalation rate | Cases escalated ÷ cases reviewed | Do not treat high or low rate as quality by itself |
| Reopen rate | Closed cases reopened ÷ closed cases | State the observation window and reopen definition |
| Evidence completeness | Required evidence fields present ÷ applicable fields | Distinguish unavailable fields from reviewer omissions |
| Reviewer agreement | Agreement under a documented label set | Report sample, adjudication, and agreement statistic |
| Quality error rate | Material audit errors ÷ audited cases | Define error severity and independent sampling method |

## Reporting principles

- Include numerator, denominator, timeframe, case mix, exclusions, and definitions.
- Disaggregate by complexity or case type when useful and privacy-safe.
- Pair speed metrics with accuracy, rework, and reviewer-wellbeing safeguards.
- Do not publish small-cell sensitive data or identifiable case details.
- Never infer individual productivity or team performance from a metric without context.

No counts are shown because no real investigation dataset is included in this repository.
